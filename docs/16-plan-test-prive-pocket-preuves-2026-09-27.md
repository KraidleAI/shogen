## 2. Protocole T-A (test local, jamais un réseau réel)

1. **Isolation** : bac à sable sur F: (`F:\tmp\pocket-test\`), **aucun réseau** pendant le test hors la récupération initiale du code source ; **jamais** MainNet, **jamais** Beta/Alpha TestNet, aucun claim réel, aucune clé de compte, aucun POKT. Le worker n'a pas accès aux variables d'environnement de la machine (lancement `env -i` avec `PATH`, `GOPATH`, `GOCACHE`, `GOMODCACHE` sur F:, `GOFLAGS=-mod=mod`, `GOPROXY` autorisé pour le seul téléchargement des modules puis `GOPROXY=off`).
2. **Source épinglée** : tarball `codeload.github.com/pokt-network/poktroll/tar.gz/a109dd0bae65c1d96b010d65f4cdc5bc77a50fc2` (commit déployé, protocole §1ter) ; sha256 du tarball consigné ; `smt` v0.14.1 tel que résolu par `go.mod` (sha du `proofs.go` attendu `be819710…`, P-11) ; `go.sum` fait foi (ADR-0012 : le lockfile fait foi).
3. **Outillage** : toolchain Go **exactement** celle de `go.mod` du commit (à lire ; installation depuis `go.dev/dl` avec sha256 publié vérifié — **R-8 : vérification registre préalable, décision orchestrateur, consignée**) ; installée sous `F:\tools\go\<version>\`, rien sur C:.
4. **Test écrit, pas une exploration — options (a)+(b) FUSIONNÉES** (avis advisor C-1, 27/09) : deux niveaux, jamais l'un sans l'autre.
   - **Niveau bibliothèque (b), unitaire, bon marché** : sur `smt` seul, spec **on-chain exacte** `protocol.NewSMTSpec` (jamais un `WithPathHasher`/`WithValueHasher` de test), `Update(k, relayBytes, w)` avec **k ≠ relay.Hash**, `ProveClosest(target)`, `VerifyClosestProof` ⇒ asserter accepté. Isole la sémantique de la bibliothèque et tourne même si le harnais keeper est difficile à monter.
   - **Niveau keeper, bout en bout** : (a) session de test + UNE relation valide (requête signée en anneau, réponse signée par l'opérateur, sous la cible de difficulté) ; (b) SMST où la relation est insérée à **N chemins non canoniques** (N = 2, 16, 1 024) ; variante (b') : N réponses signées différentes à la même requête ; (c) claim (racine, compte N) + preuve « closest » pour un chemin cible du keeper ; (d) **appeler la voie de RÈGLEMENT** (`EnsureValidProofSignaturesAndClosestPath` / EndBlocker de règlement), **jamais `EnsureWellFormedProof` seul** (sinon faux négatif classé à tort RÉFUTÉ).
   - **Trois assertions anti-faux-positif obligatoires**, imprimées dans la sortie brute : (i) clé insérée ≠ relay.Hash ; (ii) chemin de la feuille prouvée ≠ `ph.Path(H(relation))` ; (iii) la feuille prouvée est bien la plus proche (`Depth`/`FlippedBits` cohérents) — pour séparer **T-A (position)** de **T-A′ (proximité, réfutant pt 6, faiblesse distincte)** : ne pas conclure T-A si N est trop petit pour exclure un bypass de proximité.
   - **Trois contrôles** : **positif** (la même relation à son chemin canonique passe, dans le MÊME harnais, avant toute conclusion — sinon INDÉTERMINÉ) ; **négatif** (signature invalide ⇒ rejet) ; **spécificité** (relation valide à clé non canonique MAIS **signature invalide** ⇒ rejet, prouve que la valeur est toujours vérifiée ; sans lui, un PASS pourrait signifier « tout passe »).
   - **Oracle** : T-A **CONFIRMÉ** ssi cas principal `nil` **ET** positif `nil` **ET** négatif/spécificité en erreur ; erreur nommant chemin/hash au règlement ⇒ **RÉFUTÉ** (citer la ligne) ; toute anomalie de contrôle ou de montage ⇒ **INDÉTERMINÉ**, jamais reclassé.
   - **À vérifier avant de conclure « le compte N est réclamable »** : qu'aucun contrôle de `Count`/`Sum` n'existe côté **`x/tokenomics`** au règlement (hors `x/proof`, non balayé par le grep du chercheur) — sinon la position serait libre mais le compte borné ailleurs.
   - **Épinglage** : re-vérifier au sha les fichiers (`proof_validation.go` `d269c190…`, `smt/proofs.go` `be819710…`) ; les numéros de ligne de l'avis advisor (WebFetch, résumé par petit modèle) sont **[2nd]**, le worker re-cite au sha épinglé (R-1 sur le worker).
5. **Ce que le test ne fait pas** : il ne mesure pas le gain (borné par le budget d'app, protocole §4.2) ; le rapport ne doit **jamais** glisser d'« existence ≠ compte » vers « exploitable » ; il n'exécute rien contre un validateur, ne produit aucun outil réutilisable ; le code de test est **gardé dans le dépôt privé Shōgen sous `scratch/pocket-test/`**, jamais poussé — **attention, la worktree MONARK courante est un dépôt public : le test n'y est jamais committé**.
6. **Sorties** : rapport de mission (verdict + ligne de code de chaque contrôle au sha + les trois assertions imprimées + sha des fichiers lus + sortie brute `go test -run … -v`), et rien d'autre.

## 2 bis. Protocole P-02 (substitution de charge utile — système TIERS) et P-09 (gonflement par feuilles groupées) — ajoutés au checkpoint-1 (C1/C2)

**P-02 (substitution de charge utile, protocole §2.2).** Objet : un intermédiaire entre RelayMiner et gateway peut-il remplacer `payload` en gardant `payload_hash` et la signature, et passer `ValidateRelayResponse` (shannon-sdk `relay.go`) ?
- Test : construire une `RelayResponse` v0.1.25+ valide, remplacer les octets de `payload` en gardant `payload_hash` et la signature, passer à `ValidateRelayResponse`.
- **Oracle** : accepte ⇒ **CONFIRMÉ** (le SDK ne compare pas SHA-256(payload)=`payload_hash`), cite la ligne au sha ; compare et rejette ⇒ **RÉFUTÉ** (cite le contrôle) ; anomalie ⇒ **INDÉTERMINÉ**. **Contrôle positif** : payload cohérent passe.
- **P-02 est une faiblesse d'un système TIERS** (shannon-sdk), pas de nos artefacts : divulgation **gatée** (§5), jamais un fait à publier.

**P-09 (gonflement par feuilles groupées, protocole §4.3ter) — SIMULATION.** Objet : regrouper des feuilles fausses sous un préfixe commun ⇒ une feuille « la plus proche » passe la validation ≈ 99,99 % du temps.
- Test : construire localement des arbres à feuilles groupées, tirer des cibles, mesurer le **taux de passage** de la validation closest.
- **Oracle** : taux mesuré + IC, marqué **[mesure, simulation]** ; **jamais** présenté comme faille prouvée sur mainnet ; un taux < 100 % nuance P-09.
