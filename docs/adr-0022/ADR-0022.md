# ADR-0022 — Révision de τ : seuils PAR CLASSE (BTC/USD, campagne S2)

- **Statut** : proposé — checkpoint #1 validateur-humain ACCEPTÉ-AVEC-CORRECTIONS (C1-C7 intégrées ci-dessous) ; implémentation → G2 → oracle local → G7 → checkpoint #2 → commit.
- **Date** : 2026-08-26.
- **Rattachement** : clôture ADR-0020 (clause de révision τ), ADR-0021 (σ par classe + patron de garde scalaire-legacy), doc 10 §5.2/§5.6/§6.1, doc 04 §3, ADR-0003 (recalculabilité).
- **Mandat** : décision déléguée à l'orchestrateur par l'investisseur (« prends la décision après faits + recherche + rigueur académique + advisor »), 2026-08-26.

## Contexte

La clôture de calibration S2 (2880 fenêtres, BTC/USD, dim. 23/08 00:00 UTC) a **déclenché la clause de révision pré-engagée d'ADR-0020** : `tau_revision_needed = true` (P99 écart relatif honnête 0,375 % > seuil 0,25 %). Le driver campagne fail-close (rc=3) sans τ committé — campagne 26 j tenue en attente. Trois faits imposent la forme :
1. La spec dit **`τ_classe`** (par classe) depuis l'origine (doc 10 §5.2, §6.1) ; ADR-0020 l'avait figé à un scalaire uniforme 0,5 % *tout en rendant σ par-classe*.
2. Le drapeau τ (hors-enveloppe) **nourrit le signal central** : `classify_ecart`→`HORS_ENVELOPPE` ∈ `ECARTS` (r1.py:76) construit la matrice φ (`lm.pair_phi`) que `drapeau_2` (co-défaillance, doc 04 §3) consomme.
3. **Hétérogénéité 8×** entre classes (agrégateurs P99 0,72 % vs places 0,07 %). Le scalaire committé 0,5 % projette **793 faux-drapeaux honnêtes/26 j** (échoue des deux côtés).

## Décision

**τ devient PAR CLASSE.** Valeurs de DÉPART (BTC/USD), **une seule règle uniforme pour les 5 classes** :

> `τ_classe = grid-ceil( 1,5 × max(écart relatif honnête, sur les DEUX strates), 0,05 % )`, bornée `> max honnête` et `< plus petit événement réel pertinent (CAPO 2,85 %)`.

| classe | membres | max honnête (2 strates) | **τ** | note |
|---|---|---|---|---|
| oracle_pyth | pyth | 0,0746 % | **0,15 %** | |
| place_horodatee | coinbase, okx_ticker, okx_index, bitstamp, gemini | 0,2794 % | **0,45 %** | max en strate *stress* |
| sans_horodatage | binance, kraken, bitfinex | 0,2962 % | **0,45 %** | max = bitfinex |
| oracle_chainlink | chainlink | 1,0946 % | **1,65 %** | max en strate *stress* ¹ |
| agregateur | coingecko, defillama | 1,7319 % | **2,60 %** | max = defillama |

**¹ Chainlink — la valeur suit la MÊME règle 1,5×max (pas d'ancre spéciale).** Le seuil de déviation documenté **0,5 %** (BTC/USD Ethereum Mainnet) *explique* pourquoi le max honnête de chainlink est élevé (son prix on-chain ne bouge qu'au franchissement de 0,5 % ou au heartbeat ~1 h → son lag vs la médiane atteint 1,0946 %), mais il ne *dérive pas* le τ. **Bande aveugle assumée** : 1,0946 % → 1,65 % (élargie de ~55 bps) — aucun événement documenté « à capter » n'y tombe (le plus petit = CAPO 2,85 %). σ reste par-classe (clôture P99 staleness). Le facteur 1,5 est une **marge de robustesse nommée** (50 % au-dessus de la queue honnête 48 h, contre le sous-échantillonnage d'une fenêtre courte).

## Méthode (rigueur académique, sources vérifiées)

- **Percentiles/maxima empiriques** (déjà dans `closure.py`), PAS un k-σ normal : distribution à **queue lourde** (max 1,73 % vs P99 0,375 %). SPC/ARL (NIST/SEMATECH, k=3σ, ARL₀≈371) suppose la normalité — cité comme précédent d'un taux de fausse-alarme non nul canonique, non appliqué. EVT/POT (Coles 2001) exclu (N≈34 500 couvre ≤P99,95). FDR/BH (Efron 2010 Ch.4) hors cadre (seuil fixe, pas tests simultanés). [chercheur Sonnet 5, Q6, [lu] primaire ; Q4/Q6 repris via artefacts concordants]
- **Plancher de fausse-alarme HONNÊTE** : la borne sup de Clopper-Pearson (k=0) projette ≤ **13·ln20 ≈ 38,9 lectures/classe/26 j** (95 %, indépendant de N) — l'incertitude irréductible d'une calibration de 48 h. Observé = 0 ; **on ne revendique PAS « 0 »**.
- **Chainlink** : 0,5 % BTC/USD **Ethereum Mainnet** (`0xF403…88c` via `ethereum-rpc.publicnode.com`) confirmé par (a) data.chain.link ×2 extraits, (b) 120 rounds on-chain, (c) **notre propre journal : signature 0,5 %/heartbeat à 92,1 %** (sortie reproductible de `scratchpad\chainlink-signature.py`, non un chiffre embarqué).
- **Événements réels** (borne sup de τ) : CAPO/Aave **2,85 %** ([lu] post-mortem officiel) ; USDe oracles Chainlink 65 bps / Pyth 4,3 % (LlamaRisk).

## Vérification adversariale (R-21) — 3 réfutants Opus 4.8 indépendants

**Précision v1/v2 (correction C1).** Les réfutants ont d'abord attaqué une **v1** (τ 0,30/0,30/1,75/1,30) : `REFUTE-arith` a confirmé ses P99, bornes CP, épisodes et τ **bit-identiques** (CP implémentée 4 façons), MAIS `REFUTE-arith`/`REFUTE-contraintes`/`REFUTE-methode` ont trouvé trois défauts — **borne CP décorative** (calculée, non câblée : la règle s'effondrait en grid-ceil(max)), **max lu sur la mauvaise strate** (place 0,1568→0,2794 %), **ancre chainlink = mauvaise quantité** (delta inter-round ≠ déviation par-fenêtre). La **v2** (présente décision) corrige les trois. Ce qui fonde la v2 :
- les **maxima sur les 2 strates** sont bit-vérifiés (`REFUTE-arith` §1/§4) ;
- la règle `grid-ceil(1,5×max)` est triviale et recalculable (`derive_tau_v2.py`, reproduite bit-identique après une coupure de courant) ;
- la table k=1,5 de `REFUTE-methode` (Attaque 4) reproduit indépendamment **4 des 5** valeurs ;
- **chainlink 1,65 % est une valeur NOUVELLE** (aucun réfutant ne l'a produite ; `REFUTE-contraintes` recommandait « garder 1,30 %, re-justifier ») — elle découle de l'application uniforme de la règle sur un max bit-vérifié (1,0946 %).

### Report du volet closure (amendement post-G2, défaut D1)

Le plan listait « `closure` clause de révision PAR CLASSE » (Conséquences item 1). Elle est **reportée à l'ADR de re-dérivation** (post-1er-week-end), report ici **DÉCLARÉ** (jamais rogné en silence, règle Dettes) et justifié par la revue G2 (5 probes) :
- La sortie `tau_classe` de `closure` (scalaire `tau_base` OU `null`, closure.py:173) est **rejetée par le loader dans les DEUX branches** → **aucun chemin** où `closure` produirait un `sigma-tau.json` campagne valide-mais-faux.
- Le `sigma-tau.json` committé est **assemblé** σ(clôture)+τ(ADR), jamais la sortie brute de `closure` (le `test_roundtrip` réécrit le prouve).
- La clause per-classe n'est exercée que par le mécanisme de re-dérivation (ADR futur) et n'est **pas testable** sur le journal de calibration scalaire dans cette passe (rupture ADR-0003 déclarée, C4). Résidu mineur consigné : un τ non-numérique dans le fichier committé → `InvalidOperation` (fail-closed) au lieu du `SigmaTauNonRepresentable` propre — miroir exact du chemin σ, pré-existant, hors périmètre.

## Alternatives écartées

- **τ scalaire révisé** (ex. 1,0 %) : 793 faux-drapeaux/26 j, aveugle les flux serrés — rejeté.
- **τ = 3×P99** : 3×P99 agregateur (1,675 %) < son max honnête (1,73 %) — sous-couvre par construction ; écarté aussi par l'advisor (esthétique).
- **chainlink « garder 1,30 %, re-justifier »** (`REFUTE-contraintes` §6.5) : décliné au profit de la règle uniforme (1,65 % = 1,5×max) — cohérence de règle > minimisation locale de la bande aveugle.
- **sans_horodatage 0,50 %** (= scalaire committé, `REFUTE-contraintes` §6.3 « ne pas resserrer sous la valeur committée ») : décliné au profit de 0,45 % (règle uniforme, 1,52× le max bitfinex 0,2962 %) — le committé 0,5 % n'a pas de statut normatif ici.
- **Facteurs de marge par-classe distincts** : 1,5× uniforme est la règle la plus simple et défendable ; toutes les valeurs tombent dans [max honnête, événement réel].
